# Этап 0: проверка интеграции с GIMP

Проверено 11 сентября 2026 г. на установленном GIMP 3.0.0 под Windows.

## Воспроизведение

Из корня репозитория запустить `./tools/run_probe.ps1`. При нестандартной установке передать `-GimpRoot` с путём к каталогу GIMP.

Скрипт запускает отдельный экземпляр `gimp-console-3.0.exe` через штатный `python-fu-eval`, без интерфейса. Профиль находится в `.stage0/profile`, результаты — в `.stage0/output`, журнал — в `.stage0/console.log`. Эти файлы исключены из Git. Рабочий профиль и открытые изображения пользователя не используются. Соответствие активного профиля ожидаемому пути проверяется утверждением в коде.

## Подтверждено запуском

- ✓ Установленный GIMP предоставляет Python 3.12 и GI API Gimp 3.0.
- ✓ Выполнение Python-кода внутри отдельного экземпляра GIMP через пакетный интерпретатор работает.
- ✓ Пользовательский постоянный `Gimp.Parasite` с JSON сохраняется в XCF и восстанавливается с точным совпадением байтов после загрузки.
- ✓ Тестовый документ после загрузки содержит один исходный графический слой; для хранения параметров отдельный слой не создаётся.
- ✓ В пространстве имён Gimp отсутствуют типы с именами Canvas, DrawTool и ToolWidget; у Gimp.Display нет собственных сигналов. Это получено из установленного API, а не предположено по версии редактора.
- ✓ Среди зарегистрированных процедур, отобранных по canvas/display/tool/pointer/event/overlay, обнаружены только операции создания, удаления, показа, переподключения и обновления дисплеев и получения дескриптора окна.

Журнал содержит предупреждения штатных Script-Fu о ресурсах, отключённых параметром `--no-data`, и недоступности проверки обновлений. Пакетная команда завершилась успешно, отчёт сформирован, проверка XCF пройдена.

## Ограничение выбранного подхода

Для обычного Python-плагина через публичный API установленного GIMP не найден механизм подключения к событиям мыши основного холста и регистрации собственного служебного наложения. Методы Gimp.Display управляют представлением изображения, но не дают доступ к его GTK-виджету. Получение дескриптора окна не предоставляет готовые координаты холста, масштаб и события редактора.

Следовательно, вариант «обычный Python-плагин с собственным интерактивным инструментом и независимым цветным наложением на основном холсте» пока не имеет подтверждённого пути реализации. Прототип с перетаскиванием не создан; проверку мышью пользователю пока предлагать нечего. Это ограничение интеграции, а не геометрии или производительности Python. Переход на C при сохранении того же публичного API сам по себе проблему не решает.

Источники для сопоставления: [Gimp.Display](https://developer.gimp.org/api/3.0/libgimp/class.Display.html), [каталог публичного API](https://developer.gimp.org/api/3.0/libgimp/), [Gimp.directory](https://developer.gimp.org/api/3.0/libgimp/func.directory.html). Отчёт установленной версии сохраняется в `.stage0/output/report.json` и содержит полный перечень процедур.

## Варианты для обсуждения

1. Исследовать использование штатных контуров GIMP и инструмента их редактирования как управляющих элементов. Это компромисс: контуры являются объектами XCF и могут быть доступны без плагина; защищённость, оформление и автоматическое обновление сетки ещё не подтверждены. Не выдавать этот вариант за выполнение всех текущих требований.
2. Исследовать отдельное Windows-приложение-помощник с наложением поверх окна GIMP. Исходники GIMP менять не потребуется, но это уже не обычный плагин. Синхронизация масштаба, прокрутки, вкладок, DPI и ввода — самостоятельные риски; реализуемость ещё не проверена.

Изменение самого GIMP исключено пользователем. Ни один компромисс не внедрять без выбора пользователя.

## Что остаётся непроверенным

- ☐ Управление точкой и сеткой на основном холсте.
- ☐ Служебное отображение поверх всех слоёв во время работы кистью.
- ☐ Отмена действий, масштабирование, прокрутка и точки за пределами изображения.
- ☐ Сохранение и повторная запись XCF в отдельном запуске без установленного пользовательского плагина с последующим восстановлением конструкции. Выполненный тест пока проверяет сохранение/загрузку данных через штатный пакетный интерпретатор.
- ☐ Экспорт изображения без сетки: сама сетка ещё не реализована.

Этап 0 остаётся в работе. Дальнейший путь интерактивной интеграции требует решения пользователя.
